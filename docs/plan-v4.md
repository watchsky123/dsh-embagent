# 方向重规划 v4 —— 从「判得准」转到「出得了板」

> 触发点：拿到大佬的《嘉立创EDA × DSH 接入与实战手册》（1661 行）后，
> 按它重测了一遍 P17 的发射链路。**结论有翻转**：卡了很久的「自动布线布不出来」
> 不是环境问题，是我自己的板框坐标写反了。这条一修，`route=native` 直接通，
> 于是整条「出板」链成了主力方向，判定层退回配角。

## 0. 先说结论

| 项 | 之前 | 现在（实测） |
|---|---|---|
| `route=native` | `not_ready`（"引擎拒绝"/"headless 没执行环境"） | **`ok`**：2/2 网布通、9~11 段 45° 单层走线、0 过孔、DRC 零违规、`save=True` |
| 板框 Y 轴 | 「未对照，矩形不受影响」 | **已对照**：`R` 原点是左上角、向 −Y 延伸；写反＝板框在负 Y，元件全在板外 |
| 手册 §15.1（API 建工程无云槽位） | 未验，准备照抄迁移配方 | **本机不成立**：`data` 有槽位、`sch_Document.save()` 真、元数据 API 正常 |
| 手册 §17.12（`autoRouting` 运行时不存在） | 未验 | **本机不成立**：函数在，返回完整 `IPCB_AutoRoutingResult` |
| 原理图打法 | 逐引脚拉短线 + 网络名（已实现） | 与手册 §13.1 **一致**，不用改 |

一句话：**能打板的主链路已经通了**，接下来缺的不是判定，是「出板的完整性」——
铺铜、DRC 可信度分级、几何连通性判定、以及把立创通道从"能用"变成"稳"。

### 1.3 手册没写、这次自己挖出来的

1. **CLI 窗口是「未登录」态**：用户登录后，`createProject` 在 `origin=cli`
   窗口里抛 `Cannot read properties of undefined (reading 'username')`。
   同一次登录几分钟后又成功了 —— 说明是**登录态切换期的竞态**，
   不是永久限制。⇒ 发射的 `project` 段必须把这类失败**报成 not_ready 并说清**，
   不能吞。
2. **`session list` 有 `origin: cli|user`，且 CLI 能 `invoke` 进用户窗口。**
   这是手册里没有的通道：不用装扩展就能在"用户那扇登录着的窗"里跑代码。
   （代价：`session close` 对 user 窗口是**销毁**，我今天误关了用户窗口一次。）
3. **`r3demo` 的 PCB 是空的**（0 元件 —— P17 那 4 个件全是 `no_symbol`）。
   拿它做布线实验只会得到 `totalNetsCount: 0`，证明不了任何事。
4. **`autoRouting` 内部 900 秒硬上限，且"失败/超时后中间几何结果不提交"**；
   要中间结果只能用 `startAutoRouting` 作业模型（本机 `jobId` 查不到＝作业没建立）。
5. **`IPCB_AutoRoutingProps` 真实字段**：`RoutingNets`（大写 R）、`cornerStyle`、
   `existingPrimitiveMode`（`'keep'`/`'remove'`）、`optimization`、`layers`、`ignoreNets`。
6. **工程文件夹名 = `friendlyName`（可含中文/空格），根文件名 = `<friendlyName>.eprj3`。**
   用 `projectName` 拼路径会打不开（我踩过一次，读成空工程）。

## 2. 这一轮的翻转：板框 `R` 模式原点

### 2.1 证据链（每一步都是实测）

```
autoRouting()          → {success:true, totalNetsCount:2, successNetsCount:0,
                          failedNets:["GND","MID"], duration:815}
             ↑ 先怀疑环境：换可见窗口 / 换 origin=user 登录窗 / 换登录态
             全部 → 仍然 0/2
             ↑ 再怀疑几何：读板框
polyline.getState_Polygon().getSource() → ["R", 0, 0, 1968.5, 1574.8, 0, 0]
焊盘坐标                                → y ∈ [472, 1102]
             ⇒ R 的 (x,y) 是左上角、向 −Y 延伸 ⇒ 板框落在 y∈[-1575,0]
             ⇒ 元件全在板框外 ⇒ 无地可布
```

### 2.2 改一行

```python
- ["R", mm_to_mil(x0), mm_to_mil(y0),          mm_to_mil(w), mm_to_mil(h), 0, 0]
+ ["R", mm_to_mil(x0), mm_to_mil(y0 + h),     mm_to_mil(w), mm_to_mil(h), 0, 0]
```

### 2.3 修后（同一块板）

| 量 | 修前 | 修后 |
|---|---|---|
| `successNetsCount` | 0 / 2 | **2 / 2**，`failedNets: []` |
| 盘上走线 | 0 | **9 段**（GND 5 / MID 4），全 45°、全单层 |
| 过孔 | 0 | 0 |
| DRC | — | `[]` |
| 关会话重开后 | — | 元件 3、板框 `['R',0,1574.8,…]`、9 段走线全在 |
| `check_p17` 第 2 条 | `not_ready` | `ok`（tracks 11 / vias 0 / 2 网 / 0 违规） |

### 2.4 连带修的「判据读错字段」

`successNetsCount` 不是"板子通不通"，是"这次调用做了什么"。判定改成**量几何**：
每个 ≥2 焊盘的网络都必须有走线；空设计/单焊盘网 → `not_ready`（不是通过）。
新增三条纯函数断言（`check_p17` 4a/4a2/4a3）。

## 3. 重新规划：P24 → P32

原则不变：**判定只在 Python 一份**、**缺失≠通过**、**每条闸门有出口**。
变化的是**主线**：从"把判定做厚"改成"把板做出来、把每条证据链钉死"。

### P24 立创通道两条腿（不可用时必须能说清）

- 现状：只有 CLI（`invoke --session`）。Bridge 起了但 `edaConnected:false`（缺扩展）。
- 要做：
  - `design/lceda_channel.py`：`cli` / `bridge` 两个后端，同一套 `invoke(script)`
  - `session list` 里区分 `origin=user/cli`；**关闭策略按 origin 分叉**
    （user 窗口绝不 `close`，只释放句柄 —— 今天误关过一次）
  - Bridge 可用性自检 → `not_ready` + 手册 §3.2 的三步指引（勾权限→重启→Reconnect）
  - **登录态竞态**：`createProject` 抛 `username undefined` → 重试一次 + 明确报错文案
- 判据：同一段代码在两个后端返回**逐字段一致**；无扩展时 `bridge` 后端 `not_ready` 且点名缺扩展。

### P25 发射的"落盘真值"（不再假装保存了）

- 现状：`_run_pcb` 里 `attempt('save')` 的返回值**只进 steps，不进判定**；
  回读路径已能读网表，但**从没断言过"关会话重开后元件还在"**。
- 要做：`save()` 返真 → `ok`；返假 → `not_ready` 并点名；
  新增 `verify_persisted()`：关会话、重开、读元件/走线/板框条数，与关闭前比。
- 判据：人为把 `save()` 变假 → `route`/`pcb` 段必须红（退化验证）。

### P26 几何回读：`design/pcb_geo.py`

- 目标：把「板上到底有什么」变成可离线复算的数据：
  元件（位号/坐标/层/旋转）、焊盘（net/number/x/y/layer/hole）、板框（源数组+实际 y 区间）、
  走线（net/两端坐标/层/线宽）、过孔、飞线总数、DRC 分组。
  **落点**：`BoardGeometry.to_dict()`，进 `emit.json` 的 `route_detail`（不单独开文件，
  避免又多一个事实源）。
- 为什么单独做：P27/P28/P29 三条都要它；而现在的读法散在 `.replace("__CTX__", …)`
  的 JS 里，**没法离线验**。
- 判据：焊盘数与 EDA 自报一致；板框 y 区间必须包含全部焊盘（这条就是 P17 那个 bug 的判据）。

### P27 连通性判定器（几何并查集）

- 手册 §21 那 40 行搬到 Python，吃 `pcb_geometry.json`：
  焊盘-走线-过孔按**几何接触**建并查集，逐网络判 `ALL CONNECTED(n)` / 分成几组。
- 必须处理的坑：焊盘形状 `RECT` 与 `POLYGON` 取半宽（手册踩过 `NaN` → 明明连着报断开）。
- 为什么值：DRC 的 `Connection Error` **不可信**（§18.1：不认 API 过孔）；
  这个判定器不依赖 DRC，也不依赖 EDA 内部网表。
- 判据：合成夹具（一段走线差 1mil 没搭上）必须判"断开"；真实板判"全连通"。

### P28 布线兜底：`route=ours`

- 现在 `native` 能用了，这条降级为**兜底**（引擎布不通时、或未来离线批量时）。
- 内容：栅格迷宫（单层优先，过孔仅兜底）＋ 45° 倒角（§20）＋
  **8 参数标量** `pcb_PrimitiveLine.create(net, layer, x1,y1,x2,y2,w,lock)`
  （§17.12：折线数组形式不可用）＋ 批 ≤14 段。
- 判据：P27 判定器判全连通；DRC `Clearance` 零违规（`Connection` 只记录）。

### P29 铺铜（GND 真正连上的唯一办法）

- 现状：**完全没有铺铜**。小板上引擎能用走线把 GND 布通，但真实板 GND 靠铺铜。
- 要做：双面 GND 铺铜（§19 坐标 + §17.15 单面铺不到 SMD 焊盘）、
  `rebuildCopperRegion()` → `getCopperRegion() != null` 才算成（§19.2）、
  孤岛焊盘补缝合过孔（§17.16）、过孔尺寸查规则（§17.17）。
- 判据：`getCopperRegion()` 非空；铺铜后 DRC 的 GND 未连接数下降。
  **只报"铺铜成功"不算通过**。

### P30 原理图/PCB 批处理与幂等

- 现状：整板一次装；器件多时会撞 30s 预算。
- 要做：器件 ≤6/批、导线 ≤14/批、读操作 ≤12/批；每批后可续跑；
  重复发射仍是**新工程**（不覆盖，P17 的决定不变）。
- 判据：≥40 个器件的夹具能装完且网表 parity 全等（现在是"要么一次成功要么全废"）。

### P31 制造输出落盘（真能打板的那一步）

- 现状：`outputs` 段生成 Gerber/BOM/坐标成功，**落盘被权限拦** →
  `not_ready`，`saved: 0`。
- 要做：① Bridge/扩展通道下 `saveFileToFileSystem` 可用则直接写；
  ② 否则把内存文件**经 `File.text()` / base64 读回，由 Python 落盘**
  （P17 已经证明 `getDsnFile` 能读出 10928 字节的 `File`）。
- 判据：产物目录里出现 Gerber zip（非空、能被 `zipfile` 打开）+ BOM + 坐标文件；
  读不回 → `not_ready`，不许记 ok。

### P32 DRC 分级 + 进交接单

- 要做：`drc` 证据按 `Clearance` / `Connection` / `Netlist` 三分组计数，
  `Clearance` 才是判据，`Connection` 只作提示（§18.1 实测规律），
  全部进 `handoff` 的 `external` 类。
- 现状遗留：`check_p17` 第 4b 条显示布线后 `read_back` 口径 DRC 有 **5 条违规**
  （路由段自己量到 0）。**这条没查清**：可能是 `Connection`/`Netlist` 类误报
  （手册 §18.2：手工摆放的 PCB 与原理图网表对不上必然报 Netlist Error）。
  P32 第一件事就是把这 5 条**分类看清楚**。
- 判据：分组计数非空且能对上实际违规；退化验证：把分类改成一锅端，断言红。

## 4. 优先级

```
先做（出板链闭环）      P25 落盘真值 → P26 几何回读 → P27 连通性判定
再补（板子像板）        P29 铺铜 → P32 DRC 分级（先查清那 5 条）
兜底（引擎失效时）      P28 自研布线
优化（规模）            P30 批处理 → P31 制造输出落盘
可选（换通道）          P24 Bridge 后端
```

理由：
- **P25 最便宜、风险最高**——"保存了"这件事现在**没有断言**，而它是"能不能打板"的前提。
- **P26/P27 是"证据链"**：没有几何回读，布通与否只能信 EDA 的自述（而我们刚被自述骗过两次）。
- **P29 铺铜**是真实板 GND 的唯一来源；小板可以靠走线，大板不行。
- **P28 自研**在 `native` 已通之后**不是优先项**——只在引擎布不通时才需要。
